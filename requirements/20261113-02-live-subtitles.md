# 实时字幕、模型配置拆分与音色试听

- 编号：20261113-02
- 状态：已完成
- 版本：v2
- 创建日期：2026-11-13
- 确认记录：v2 于 2026-11-14 确认

## 背景

用户希望说话时边说边显示识别出的原文（流式字幕），而不是一句话说完才出现。经查官方文档：

- `gemini-3.8-live` 的输入识别文字只在一句话结束后返回，文档没有提供实时（interim）识别结果。
- 实时识别结果 `interimInputTranscription` 由专门的转写模型 `gemini-3.5-transcribe-live` 提供（[Live transcription 文档](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe)）。这个模型只输出文字，不能翻译和朗读。

用户选择"方式一"：说话时把同一份麦克风音频同时发给翻译播报模型和转写模型，转写模型只负责实时字幕，翻译和播报仍由翻译播报模型完成。

同时提出两项配套需求（用户原话）：

- 因为同时存在实时字幕和翻译播报两个场景，对配置页面的 Live API 模型选择做对应优化。
- 播报音色选择之后，增加音色预听（试听）功能。

## 目标

1. 说话过程中，当前说话一侧的字幕区随着说话持续刷新识别出的原文。
2. 配置页能分别设置"翻译播报模型"和"实时字幕模型"，并能一起测试连接。
3. 选择播报音色后能马上试听该音色。

## 需求范围

### 一、实时字幕

1. **连接**：开始对话时，除现有的两条翻译播报连接外，再为中文、英文两侧各建一条实时字幕连接，使用设置中的"实时字幕模型"（默认 `gemini-3.5-transcribe-live`）。
   - 配置：只返回文字，开启输入识别，识别语言按该侧固定（中文侧 `zh-CN`、英文侧 `en-US`，最终代码以官方支持语言表和实测为准）。
   - 按住说话模式下，字幕连接和翻译播报连接一样改为手动控制句子起止。
2. **音频**：当前说话一侧收音时，同一份麦克风音频同时发给该侧的翻译播报连接和字幕连接。字幕连接不影响翻译播报连接收到的音频。
3. **显示**：
   - 收到实时识别结果时，刷新当前说话一侧的字幕区。实时结果用较浅的灰色显示，表示"还在识别中"。
   - 翻译播报模型返回最终原文后，用它替换实时字幕，改为正常颜色。对话记录和翻译都以翻译播报模型的原文为准。
   - 译文不做流式显示（与现状一致）。
4. **轮次**：
   - 字幕结果只显示在当前轮次。切换说话方、被打断、结束对话后，旧轮次迟到的字幕结果不能显示到新轮次上。
   - 译文开始输出后，不再更新该轮字幕。
5. **失败处理**：字幕连接失败、被关闭或模型不可用时，不影响翻译和播报，界面退回到现在的效果（说完后显示原文），不弹出错误；会话页顶部的连接错误信息不显示字幕连接的错误。字幕连接断开后，在下一轮开始时自动重连。
6. **关闭字幕**：设置中"实时字幕模型"选择"关闭"时，不建立字幕连接，行为与现在完全相同。
7. **打字输入、重播**：不使用字幕连接，行为不变。

### 二、配置页模型选择

1. 原"Live API 模型"一节拆成两节：
   - **翻译播报模型**：负责识别、翻译并朗读译文。预设 `gemini-3.8-live`（默认）、`gemini-3.1-flash-live-preview`、`gemini-3.5-live-translate-preview`、`gemini-2.5-flash-native-audio-preview-12-2025`，可自定义模型 ID。说明文字保留现有的模型差异提示。
   - **实时字幕模型**：负责说话时实时显示原文，不参与翻译。预设 `gemini-3.5-transcribe-live`（默认）和"关闭"，可自定义模型 ID。说明文字注明"开启后音频会同时发送给两个模型，音频费用相应增加"。
2. 「测试连接」同时测试两个模型，分别显示结果，例如"翻译播报：连接成功；实时字幕：连接失败：…"。字幕选择"关闭"时只测翻译播报模型。
3. 新设置项随其他设置一起保存在本机，已有用户升级后字幕模型默认为 `gemini-3.5-transcribe-live`。

### 三、音色试听

1. 点选某个音色后，自动用该音色朗读一句固定的英文示例句（由翻译播报模型把中文示例句"你好，我会帮你把对话翻译成英文。"翻译后朗读）。另提供「试听」按钮，可再次播放当前选中的音色。
2. 试听期间显示"正在试听…"，播放结束后恢复；再次点选其他音色时，停止上一段试听，播放新音色。
3. 试听使用设置页当前输入的 API Key 和翻译播报模型（无需先保存）。未填写 Key 时提示"请先填写 API Key"；失败时显示失败原因。
4. 翻译播报模型为 `gemini-3.5-live-translate-preview` 时，该模型不支持选择音色和文字输入，试听按钮不可用，并提示原因。
5. 离开设置页时停止试听。

## 不在范围内

- 译文的流式显示。
- 改用"先转写、再把文字交给翻译模型"的方式二。
- 实时字幕的识别结果参与翻译或写入对话记录（只用于显示）。
- 新增依赖库。
- 其他语言、离线识别。

## 验收标准

1. 配置页显示"翻译播报模型"和"实时字幕模型"两节，各自有预设和自定义输入，实时字幕有"关闭"选项；保存后重新进入设置页，两项设置保持不变。
2. 「测试连接」分别显示两个模型的结果；把字幕模型改成一个不存在的 ID 时，显示"实时字幕：连接失败"，而翻译播报显示"连接成功"。
3. 点选音色后出现"正在试听…"并能听到朗读；试听结束后提示消失；在试听过程中点选另一个音色，上一段停止并开始播放新音色。
4. 翻译播报模型选 `gemini-3.5-live-translate-preview` 时，试听按钮不可用并显示原因。
5. 开启实时字幕，用中文说一句较长的话：说话过程中至少两张不同时刻的截图显示字幕区文字在增加或变化（浅灰色）；说完后原文变为正常颜色，随后正常翻译和播报。
6. 英文一侧说话时，同样能看到实时字幕。
7. 按住说话模式下，按住说话过程中能看到实时字幕，松手后正常翻译。
8. 实时字幕选择"关闭"时，说话过程中不出现实时字幕，说完后显示原文，翻译和播报正常。
9. 字幕模型设为不存在的 ID 时，对话仍能正常翻译和播报，会话页不显示字幕连接错误。
10. 播放译文时点对方的语言按钮接话，新一轮的字幕区不会出现上一轮的识别文字。

## 影响范围

- `live/GeminiLiveClient.kt`：支持纯文字转写模式的配置；解析 `interimInputTranscription`。
- `session/ConversationViewModel.kt`：字幕连接的建立、复用、重连和关闭；麦克风音频同时分发；字幕结果与轮次绑定；音色试听；测试连接改为两个模型。
- `session/Models.kt`：界面状态增加"字幕是否为实时结果"。
- `data/SettingsStore.kt`：新增实时字幕模型设置及预设列表。
- `ui/SettingsScreen.kt`：模型选择拆为两节、测试结果分两行、音色试听。
- `ui/SidePanel.kt`：实时字幕用浅灰色显示。
- `MainActivity.kt`：把试听相关回调传给设置页。

## 风险

- `gemini-3.5-transcribe-live` 的配置格式、实时结果是"整句当前假设"还是"增量片段"、中文实时识别的延迟和准确度，都要用真实 Key 在手机上实测。开发时会先按"整句当前假设、每次替换"处理，若实测为增量片段再改为追加，并在测试报告中说明。
- 本机暂时无法连接 Google 服务器，用无效 Key 预检配置格式的步骤未能完成，改为在手机上用真实 Key 验证。
- 开启字幕后每次说话的音频上传量约为原来的两倍，音频费用相应增加。官方转写模型的计费标准待查。
- 转写连接单次最长 10 分钟，超过后由服务端断开；按"断开后下一轮自动重连"处理。

## 已确认的决策

1. 实时字幕默认开启，可在设置中关闭。
2. 实时识别结果用浅灰色显示，最终原文用正常颜色。
3. 试听示例句为"你好，我会帮你把对话翻译成英文。"翻译成英文后朗读；只试听英文，不另外试听中文。
4. 点选音色后自动试听，同时提供「试听」按钮再次播放。
5. 验收标准 5–8 的语音输入由电脑扬声器朗读测试句（中文用 macOS `say -v Tingting`，英文用 `say -v Samantha`），手机放在扬声器旁收音，测试时会有声音外放。
