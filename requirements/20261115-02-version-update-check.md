## 背景

用户原话："在设置页面增加版本信息以及版本更新检测。"

现状：

- 设置页没有任何版本信息，用户不知道自己装的是哪个版本。
- 新版本通过 GitHub Releases 发布（`docs/architecture.md`"版本号与发布"）：标签为 `vX.Y.Z`，每个版本有 5 个按架构区分的 APK，文件名为 `f2ft-X.Y.Z-<架构>.apk`。
- GitHub 公开接口 `https://api.github.com/repos/wangwei1237/f2ft/releases/latest` 无需登录即可返回最新正式版的标签、发布页地址、说明和 APK 下载地址（已验证能拿到 `v0.0.1` 及其附件）。未登录调用的频率限制为每个 IP 每小时 60 次。
- App 已有 OkHttp 和 `org.json`，不需要新增依赖。

## 目标

用户在设置页能看到当前版本，并能检查是否有新版本；有新版本时能方便地下载适合自己手机的 APK。

## 需求范围

### 一、版本信息

在设置页底部（「保存」按钮下方）新增"关于"一节，显示：

- 当前版本：`versionName`，例如"0.0.1"，后面括号注明构建号 `versionCode`。
- 手机架构：设备的首选 CPU 架构（如 `arm64-v8a`），用于说明应该下载哪个 APK。
- 项目主页链接：点击用浏览器打开 https://github.com/wangwei1237/f2ft 。

版本号从系统安装信息中读取（`PackageManager`），不修改构建配置。

### 二、更新检测

1. 在"关于"一节提供「检查更新」按钮。点击后请求 GitHub 最新正式版信息，检查期间按钮显示"正在检查…"。
2. 结果分四种：
   - **已是最新**：显示"已是最新版本"。
   - **有新版本**：显示"发现新版本 vX.Y.Z"和该版本说明的前几行，并提供两个按钮：
     - 「下载更新」：用浏览器直接下载与本机架构匹配的 APK（如 `f2ft-X.Y.Z-arm64-v8a.apk`）；找不到匹配架构时下载 `universal` 包。下载完成后由用户自行点击安装。
     - 「查看发布页」：用浏览器打开该版本的 Release 页面。
   - **开发版本**：当前版本号不是 `X.Y.Z` 格式（例如本地构建的 `1.0`）时，显示"当前为开发版本，最新发布版为 vX.Y.Z"，并提供「查看发布页」。
   - **检查失败**：网络错误、超时（10 秒）或接口返回异常时，显示"检查失败：原因"，可再次点击重试。
3. 版本比较按 `X.Y.Z` 三段数字逐段比较。
4. 检查更新只在用户点击按钮时进行，不在后台或打开页面时自动检查。

## 不在范围内

- 在 App 内下载 APK 并直接调起安装（需要新增安装权限和文件共享配置，安全审核更复杂）。
- 后台定时检查、通知栏提醒。
- 预发布版本（prerelease）和草稿的检测。
- 修改发布工作流或 Release 内容。

## 验收标准

1. 设置页底部有"关于"一节，显示当前版本号（含构建号）、手机架构和项目主页链接；装的是 Release 中的 `v0.0.1` 时显示"0.0.1（1）"和 `arm64-v8a`。
2. 点击项目主页链接，浏览器打开 GitHub 仓库页面。
3. 安装 `v0.0.1`、且最新正式版就是 `v0.0.1` 时，点「检查更新」显示"已是最新版本"。
4. 当最新正式版高于已安装版本时，显示"发现新版本 vX.Y.Z"、版本说明摘要、「下载更新」和「查看发布页」；点「下载更新」后，浏览器开始下载与本机架构匹配的 APK；点「查看发布页」打开对应的 Release 页面。
5. 安装本地构建的开发版本（版本号 `1.0`）时，点「检查更新」显示"当前为开发版本，最新发布版为 v0.0.1"。
6. 断开手机网络后点「检查更新」，显示"检查失败"及原因；恢复网络后再次点击可以正常检查。
7. 检查期间按钮显示"正在检查…"，不能重复点击。
8. `README.md` 和 `docs/architecture.md` 已按需同步更新。

## 影响范围

- 新增 `android/app/src/main/java/com/fy/facetranslate/data/UpdateChecker.kt`：请求 GitHub 接口、解析最新版本、比较版本号、选择匹配架构的 APK。
- `ui/SettingsScreen.kt`：新增"关于"一节。
- `session/ConversationViewModel.kt` 或 `MainActivity.kt`：提供检查更新和打开链接的回调。
- `README.md`、`docs/architecture.md`。

## 风险与测试方法

- 验收标准 4 需要一个比已安装版本更新的 Release。测试方法：在本机构建版本号为 `0.0.0` 的测试包（用发布密钥签名），安装后检查更新，此时 `v0.0.1` 就是"新版本"。不在 GitHub 上新建任何发布。
- Android 不允许用低版本覆盖安装高版本，所以安装测试包前要先卸载手机上的 `v0.0.1`，卸载会清除 App 内的设置（包括 API Key）；测试结束后再卸载测试包，重新安装 Release 中的正式包 `f2ft-0.0.1-arm64-v8a.apk`，需要你重新填写 API Key。检查更新本身不需要 API Key。
- 检查更新会访问 GitHub，GitHub 能看到手机的 IP 地址；不发送任何对话内容或 API Key。

## 已确认的决策

1. 只在点击「检查更新」时检查，不自动检查。
2. 用本地构建的 `0.0.0` 测试包验证"发现新版本"，不在 GitHub 上新建发布。
3. 「下载更新」用浏览器下载，由用户手动安装。
